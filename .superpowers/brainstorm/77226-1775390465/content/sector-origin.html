Sectors Are Not Containers

The critical distinction: coordinate encoding vs. spatial partitioning

What Sectors Are NOT (Minecraft Chunks)
  In Minecraft, chunks are CONTAINERS. Blocks live IN chunks.
  A block at a chunk boundary has neighbors in a different chunk.
  This creates real edge cases: lighting, physics, loading.

  ┌──────────┬──────────┐
  │ Chunk A  │ Chunk B  │      A block HERE ↓ needs to know
  │          │          │      about both chunks
  │        ██│██        │      ← straddling the boundary
  │          │          │
  └──────────┴──────────┘

  YOU DO NOT HAVE THIS PROBLEM.

  Sectors are not containers. Nothing "lives in" a sector.
  Objects don't have edges that straddle boundaries.
  No object ever needs to know which sector it's in.
What Sectors ARE (A Number Encoding)
  A sector position is just a way of WRITING DOWN a coordinate.
  It's like hours:minutes vs. raw minutes.

  "2 hours 37 minutes" and "157 minutes" are the same time.
  "sector 149600, local 23456.035m" and "149600023456.035m" are the same place.

  The Sun's POSITION is a point:
    { sector: [0, 0, 0], local: [0, 0, 0] }

  The Sun's RADIUS is 696,000 km — a scalar property.
  The radius doesn't "span" sectors any more than saying
  "I'm at 2:37 and the movie is 90 minutes" means the
  movie spans into the 4 o'clock hour "container."

  No object is "at the intersection of 8 sectors" because
  objects don't occupy sector space — they have point positions
  encoded as sector+local, and separate properties (radius, mesh
  bounds) that define their physical extent.
The Sun at the Origin — Worked Example
  Sun position:   { sector: [0, 0, 0],      local: [0, 0, 0] }
  Sun radius:     696_000_000 meters (a plain number, not a position)

  Camera (craft near Earth):
                  { sector: [149600, 0, 0],  local: [23456, 400000, 0] }

  TO RENDER THE SUN:
  ──────────────────
  1. sectorDelta = [0 - 149600, 0 - 0, 0 - 0] = [-149600, 0, 0]     ← integer math
  2. localDelta  = [0 - 23456, 0 - 400000, 0 - 0]                    ← float64 math
  3. renderPos   = [-149600 × 1e6 + (-23456), 0 + (-400000), 0]
                 = [-1.496e11, -400000, 0]                            ← one float64

  Then Three.js gets:
    position = [-1.496e11, -400000, 0]     ← far away, but who cares?
    scale    = sun radius → geometry       ← renders as a dot at this distance

  The Sun being at [0,0,0] — right at a "sector corner" — is
  the SIMPLEST case, not the hardest. There are no boundary
  lookups, no neighbor sectors to consult, no special geometry.


  COLLISION CHECK (is craft inside Sun?):
  ───────────────────────────────────────
  dist = distance(sunPos, craftPos)       ← uses sector delta + local delta
       = ~1.496e11 meters
  dist > sun.radius?  YES → no collision

  The distance function handles the sector arithmetic internally.
  The caller never thinks about sectors at all.
Where Boundaries DO Matter (and it's trivial)
  The ONLY time sector boundaries matter is normalization:
  keeping the local offset in [0, SECTOR_SIZE).

  A craft moves from local.x = 999,999.8  by +0.5 meters:

  BEFORE:  { sector: [5, 0, 0], local: [999999.8, 0, 0] }
  + 0.5m → { sector: [5, 0, 0], local: [1000000.3, 0, 0] }  ← local > SECTOR_SIZE!

  NORMALIZE:
           { sector: [6, 0, 0], local: [0.3, 0, 0] }         ← just rolled over

  This is one if-statement per axis. It happens inside the position
  update function and nothing else in the codebase ever sees it.

  function normalize(pos: SectorPosition): void {
    for (let i = 0; i < 3; i++) {
      while (pos.local[i] >= SECTOR_SIZE) {
        pos.local[i] -= SECTOR_SIZE
        pos.sector[i] += 1
      }
      while (pos.local[i] < 0) {
        pos.local[i] += SECTOR_SIZE
        pos.sector[i] -= 1
      }
    }
  }
Two Nearby Objects in Different Sectors
  Craft A: { sector: [5, 0, 0], local: [999_999.5, 0, 0] }
  Craft B: { sector: [6, 0, 0], local: [0.5, 0, 0] }

  These are 1 meter apart, but in different sectors. Is this a problem?

  distance(A, B):
    sectorDelta = [6-5, 0, 0] = [1, 0, 0]
    localDelta  = [0.5 - 999999.5, 0, 0] = [-999999.0, 0, 0]
    combined    = [1 × 1e6 + (-999999.0), 0, 0] = [1.0, 0, 0]

  Distance = 1.0 meters. ✓ Exact. No edge case.

  The sector arithmetic handles this automatically.
  There is no "different sectors" problem — just math.
